01 / NOTES

この本の到達点

SLIPSTREAMは、立体アリーナを走り、壁を蹴り、botと戦うWindows用のFPSです。この教材はその実装を題材にします。最終目標は完成コードを暗記することではありません。入力が速度になり、速度が位置になり、命中が得点になる流れを説明し、仕様を変え、壊れていないことを確かめられる状態です。

学習用の実装は独自の小規模アリーナFPSです。Quake IIIのエンジン、マップ、モデルを移植したものではなく、ネットワーク対戦や本格的なアニメーションモデルも含みません。この境界を知ると、「今のコードで改善できること」と「別の設計が必要なこと」を区別できます。

02 / NOTES

三つの層を混同しない

Common Lispは言語、SBCLはそのプログラムを実行・コンパイルする処理系です。raylibはウィンドウ、GPU描画、入力、音声を扱うライブラリ。ゲームのルール、物理、衝突、射撃、bot、試合進行はLispにあり、native/bridge.cはraylibを単純な引数で呼ぶ境界です。「LispだけでGPUまで実装する」ことが到達点ではありません。

この本は前提知識を順に導入します。第1〜7章でLispの表記とデータを覚え、第8〜12章で時間・描画・移動を作り、第13〜18章で戦闘とbotを完成させます。最後の5章ではマクロ、検証、性能、改造を扱います。数学は必要になった場面で図と数値から説明します。

Windowsで最初の式を動かす

PowerShellでwinget install --id SBCL.SBCL --exactを実行します。導入後は新しいPowerShellを開き、sbcl --versionで確認してください。PATHは既に開いている端末へ自動では反映されません。見つからない場合は、標準導入先の実行ファイルをフルパスで呼ぶと、導入失敗とPATH未更新を区別できます。

sbclを起動するとREPLが現れます。Readで式を読み、Evalで評価し、Printで結果を表示し、Loopで次の入力へ戻ります。下の(+ 2 3)だけを入力し、5が返ることを確認します。終了は(sb-ext:exit)です。sb-ext:はSBCL固有の名前空間なので、ここはCommon Lisp標準そのものではありません。

02 / NOTES

ファイルとして実行する

REPLは小さな実験に適し、.lispファイルは再現可能なプログラムに適します。例えば(format t "Hello, arena!~%")をhello.lispとして保存し、PowerShellからsbcl --script hello.lispを実行します。formatのtは標準出力、~%は改行です。REPLの「*」プロンプトや表示された結果はファイルへコピーしません。

失敗すると条件名とバックトレースが出ます。まず最初のエラー行と、そこに表示されたファイル名・行番号を読みます。「関数が未定義」と「ファイルがない」は別の問題です。初心者の段階では、何度も式を打ち直すよりファイルを直し、新しいプロセスで再実行すると状態の混乱を防げます。

この章で身につくこと

  1. 前置記法と入れ子を読める
  2. 数・文字列・シンボル・リストを区別する

01 / NOTES

一つの形で書く

関数呼び出しは(関数名 引数…)です。(+ 2 3)なら+を2と3へ適用します。(* (+ 2 3) 4)は内側の足し算を評価して5を得て、それを4倍します。括弧は装飾ではなく、どこまでが一つの式かを示す構造です。改行やインデントは読みやすさのためであり、演算の優先順位を変えません。

ゲームの位置更新も同じ形です。(+ position (* velocity dt))は「現在位置＋速度×経過秒」。速度12 m/s、dtが1/120秒なら、1回で0.1 m進みます。数字を変えて式を読むだけで、移動処理の核へもう触れています。セミコロンから行末はコメントなので実行されません。

COMMON LISP / WORKBENCH
(+ 2 3)                 ; => 5
(* (+ 2 3) 4)           ; => 20
(+ 10 (* 12 (/ 1 120)))  ; => 101/10
実験室 / READER
02 / NOTES

Lispが扱う値

整数12、浮動小数12.0、正確な有理数1/120は異なる数の表現です。Common Lispの(/ 1 120)は近似小数ではなく比を返します。単精度の型を意識する境界では1.0f0を使います。文字列は"VEX"、シンボルはhpのような名前です。キーワード:healthは自身を評価した値で、アイテムの種類を表すラベルとして便利です。

NILは空のリストでも偽でもあり、Tは代表的な真の値です。実際にはNIL以外の値はすべて条件で真として扱われ、0も空文字列も真です。JavaScriptやPythonの「ゼロは偽」という感覚を持ち込まないでください。射線距離が0のときも、命中が存在することを表せます。

COMMON LISP / WORKBENCH
(/ 1 120)     ; => 1/120
(/ 1.0f0 120) ; => a single-float approximation
(if 0 :yes :no) ; => :YES
(list "VEX" :health nil) ; => ("VEX" :HEALTH NIL)
03 / NOTES

コードを、データとして置く

(+ 2 3)は関数呼び出しですが、'(+ 2 3)は三つの要素からなるリストです。先頭の'は(quote …)の省略。quoteは引数を通常のように評価しません。(first '(+ 2 3))はシンボル+を返します。これがマクロへつながる基礎ですが、今は「地図のアイテム配置表は実行したい式ではない」ことを理解すれば十分です。

よくあるエラーは閉じ括弧不足と、データへquoteを付け忘れることです。エディタの対応括弧表示を使い、外側を一つ書いてから内部を埋めます。下の構造実験室は括弧を可視化する教材であり、Common Lispの処理系ではありません。式の実行結果はSBCLで確かめます。

COMMON LISP / WORKBENCH
(first '(+ 2 3))
(second '(0 1.2 0 :mega))
(quote (:health :armor :rail))

COMMON LISP / WORKBENCH
(let ((speed 12) (dt 1/120))

       (step (* speed dt)))
  (+ 10 step))

  (incf armor 5)

リストはつながり、ベクトルは添字

リストはconsセルの連鎖です。firstとrestで先頭と残りを取り出し、pushで先頭へ追加し、popで先頭を外します。pushは変数が指すリストの先頭を変更します。アイテムや短命なエフェクトは追加・除去が多いため、このゲームではリストとして保持します。consは二つの値を組にするので、(cons ix iz)の結果は通常の二要素リストではなく、末尾が数のドット対です。

ベクトルは一次元配列で、(aref ammo 2)のように添字でアクセスします。#(180 24 16 16)はベクトルのリテラルですが、変更する実データは(vector 180 24 16 16)で新しく作ります。ソース中の定数リテラルを破壊的に変えると、コンパイルや共有に関わる未定義の問題を招きます。弾数の順序は武器番号と一致させます。

COMMON LISP / WORKBENCH
(let ((items nil))
  (push :health items)
  (push :rail items)
  (pop items)) ; => :RAIL

  (decf (aref ammo 2))
  (aref ammo 2)) ; => 15

sortやnreverseも破壊的操作を許されます。rankedが(copy-list *actors*)をsortするのは、描画のための順位変更でゲーム本体のactor順を変えないためです。破壊的な関数の戻り値は必ず受け取ります。先頭セルが変わることがあるからです。

地図に住所を付ける

02 / NOTES

余った時間を捨てずに持つ

accumulatorへ描画間隔dtを足します。1/120秒以上たまっている間tick-gameを呼び、呼ぶごとに1/120秒を引きます。例えば1/60秒なら2回、1/144秒なら0回のフレームと1回のフレームが混ざります。端数は次へ残します。これにより、整数回の更新を無理に丸めて時間を失うことを防げます。

長時間停止した直後に何千回も更新すると、追いつくためにまた停止する悪循環が起きます。mainはフレームdtを0.1秒に制限し、ポーズ時はaccumulatorを0へ戻します。これは停止時間中の試合を完全に再現する仕様ではありません。停止から操作へ安全に戻るための選択です。オンラインゲームなら時間同期の設計は別に必要です。

外国語の関数を呼ぶ

FFIはForeign Function Interface、別の言語で作った関数を呼ぶ仕組みです。ABIは引数や戻り値を機械レベルでどう渡すかの約束です。raylibのVector3やColorをそのままLispから渡すと、構造体の配置と渡し方を正しく扱う必要があります。bridge.cはss_box(x,y,z,w,h,d,color)のような平坦な引数へ変えて、その負担をC側へ寄せます。

(defmacro native (name result &rest args)
  (let ((raw (intern (concatenate 'string "%" (symbol-name name))))
        (types '((float . sb-alien:single-float) (int . sb-alien:int)
                 (uint . sb-alien:unsigned-int) (string . sb-alien:c-string)
                 (void . sb-alien:void))))
    `(progn
       (sb-alien:define-alien-routine
           (,(substitute #\_ #\- (string-downcase (symbol-name name))) ,raw)
           ,(cdr (assoc result types))
         ,@(mapcar (lambda (a) `(,(car a) ,(cdr (assoc (cadr a) types)))) args))
       (defun ,name ,(mapcar #'car args)
         ;; Native graphics/audio code follows the usual C IEEE-754 policy.
         (sb-int:with-float-traps-masked (:divide-by-zero :invalid :overflow)
         (,raw ,@(mapcar (lambda (a)
                          (case (cadr a)
                            (float `(float ,(car a) 1.0f0))
                            (int `(round ,(car a)))
                            (t (car a)))) args)))))))

衝突は、候補を承認する処理

move-bodyはx方向、z方向を分けて候補位置を作ります。blockedなら、その軸の移動を取り消し、軸方向の速度を0にします。片方が壁に阻まれても、もう片方は更新できるので壁に沿って滑れます。body-overlapsは半径0.42と高さ1.8のプレイヤーを、箱の範囲との重なりで近似します。

この近似は厳密なカプセル形状ではなく、水平の箱拡張に近い判定です。120 Hzと速度上限は一更新の移動量を小さくしますが、あらゆる薄い障害物への連続衝突を保証しません。非常に速いダッシュを追加するなら、移動の分割かswept collisionが必要か検証してください。

        (types '((float . sb-alien:single-float) (int . sb-alien:int)
