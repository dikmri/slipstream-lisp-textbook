01 / NOTES

The work you are learning to make

SLIPSTREAM is a Windows arena FPS with three-dimensional movement, wall kicks, and bot opponents. Its implementation is the subject of this book. The goal is not to memorize its code. You should be able to explain how input becomes velocity, velocity becomes position, and a hit becomes a score; then change that behavior and verify the result.

The teaching project is an original, small arena FPS. It does not port Quake III’s engine, maps, or models, and it does not include network multiplayer or a full character animation system. Knowing that boundary helps you distinguish an improvement to this implementation from a feature that needs a new design.

02 / NOTES

Three layers, three responsibilities

Common Lisp is the language. SBCL runs and compiles programs written in it. raylib handles the window, GPU drawing, input, and audio. The game’s rules, physics, collision, weapons, bots, and match progression live in Lisp; native/bridge.c exposes raylib through simple arguments. Implementing a GPU library in Lisp is not the goal.

The book introduces prerequisites in order. Chapters 1–7 teach Lisp notation and data. Chapters 8–12 build time, rendering, and movement. Chapters 13–18 complete combat and bots. The final five chapters cover macros, verification, performance, and modifications. Mathematics is introduced through diagrams and numbers when you need it.

Run your first expression on Windows

In PowerShell run winget install --id SBCL.SBCL --exact. Open a new PowerShell afterward and verify with sbcl --version. A PATH update does not automatically reach a terminal that was already open. The REPL is ideal for small experiments; a .lisp file makes a program reproducible. Save (format t "Hello, arena!~%") as hello.lisp and run sbcl --script hello.lisp from PowerShell. Parentheses are the outline of thought

Read an expression from the inside out, not merely from left to right.

What you will learn

  1. Read prefix notation and nesting
  2. Distinguish numbers, strings, symbols, and lists
  3. Explain why quote prevents evaluation
01 / NOTES

One shape for function calls

A function call has the shape (function argument…). (+ 2 3) applies + to 2 and 3. (* (+ 2 3) 4) evaluates the inner addition to 5, then multiplies by 4. Parentheses are structure, not decoration: they mark the extent of an expression. Indentation and line breaks improve readability but do not change precedence.

Position updates use the same shape: (+ position (* velocity dt)) means current position plus velocity times elapsed seconds. At 12 m/s and dt = 1/120 second, one update moves 0.1 m. You are already reading the core of movement. A semicolon begins a comment that continues to the end of the line.

COMMON LISP / WORKBENCH
(+ 2 3)                 ; => 5
(* (+ 2 3) 4)           ; => 20
(+ 10 (* 12 (/ 1 120)))  ; => 101/10
Laboratory / READER
02 / NOTES

The values Lisp works with

The integer 12, floating-point number 12.0, and exact rational 1/120 represent numbers differently. Common Lisp’s (/ 1 120) returns an exact ratio rather than an approximate decimal. Use 1.0f0 where single precision matters. A string is written "VEX"; a symbol is a name such as hp. The keyword :health evaluates to itself and is useful as an item-kind label.

NIL is both the empty list and false. T is the conventional true value, but every non-NIL value is true in a condition, including 0 and an empty string. Do not import JavaScript or Python’s falsy-zero intuition. A ray hit at distance 0 can still represent a real hit.

COMMON LISP / WORKBENCH
(/ 1 120)     ; => 1/120
(/ 1.0f0 120) ; => a single-float approximation
(if 0 :yes :no) ; => :YES
(list "VEX" :health nil) ; => ("VEX" :HEALTH NIL)
03 / NOTES

Put code-shaped data on the table

(+ 2 3) is a call, while '(+ 2 3) is a three-element list. The apostrophe abbreviates (quote …), which prevents normal evaluation of its argument. (first '(+ 2 3)) returns the symbol +. This is a foundation for macros; for now, understand that a map’s item-placement table is data rather than a list of calls to execute.

Common early errors are missing a closing parenthesis and forgetting to quote data. Use your editor’s matching-parenthesis feature, write the outer pair, then fill in its contents. The structure lab visualizes nesting; it is not a Common Lisp runtime. Verify expression results in SBCL.

COMMON LISP / WORKBENCH
(first '(+ 2 3))
(second '(0 1.2 0 :mega))
(quote (:health :armor :rail))

Give a value a name and a lifetime

With let and setf, you can follow the state of a game.

What you will learn

  1. Distinguish the initialization order of let and let*
  2. Understand lexical locals and special variables
  3. Change values with setf and trace the writes
01 / NOTES

let creates a local workbench

In (let ((speed 12) (dt 1/120)) (* speed dt)), speed and dt are available only inside that let. This extent is their scope. A let’s initial values are evaluated in the surrounding environment, not in an environment containing their sibling bindings. Use let* when the next initialization depends on a previous one.

move-body binds p to position, velocity to velocity, and old-y to the previous height. Naming an expression is not just a way to save typing; it documents what the value means. Raycasting often uses let* because later values depend on earlier ones. let is enough for independent bindings.

COMMON LISP / WORKBENCH
(let ((speed 12) (dt 1/120))
  (* speed dt))
 
(let* ((speed 12)
       (dt 1/120)
       (step (* speed dt)))
  (+ 10 step))
02 / NOTES

The syntax of changing state

setf stores a value in a place. The same form handles (setf hp 75), (setf (actor-hp player) 75), and (setf (aref ammo 2) 10). incf and decf increase or decrease a place. Decide whether you need the old value before writing. Collision compares old and proposed heights, so the order of updates determines behavior.

Multiple place/value pairs in setf are processed left to right. If two variables refer to the same structure, a write through either reference is visible through the other. Naming an object and copying it are different operations. You will meet that distinction again with vectors and actors.

COMMON LISP / WORKBENCH
(let ((hp 100) (armor 25))
  (decf hp 10)
  (incf armor 5)
  (setf hp (min hp 100))
  (list hp armor)) ; => (90 30)
03 / NOTES

Starred names and reloading

defparameter initializes on each evaluation; defvar normally preserves an existing binding. Stars in names such as *player* and *state* conventionally identify special variables. They have dynamic scope: a temporary let binding is visible to functions called within its execution. The self-test uses that mechanism to bind *native-ready* to NIL.

defconstant declares a constant. A tunable speed or difficulty that you repeatedly redefine is better suited to defparameter. If loading a file again does not change a setting, check whether it uses defvar. Special variables are convenient here, but running multiple independent matches in a larger application would require explicit state objects.

COMMON LISP / WORKBENCH
(defparameter *training-speed* 12)
(let ((*training-speed* 20))
  (* *training-speed* 1/120))
*training-speed* ; => 12

(defun move-body (a dt)
  (let* ((p (actor-pos a)) (velocity (actor-vel a)) (old-y (v-y p)))
    (dolist (axis '(x z))
      (let* ((delta (* dt (if (eq axis 'x) (v-x velocity) (v-z velocity))))
             (candidate (v (if (eq axis 'x) (+ (v-x p) delta) (v-x p)) (v-y p)
                           (if (eq axis 'z) (+ (v-z p) delta) (v-z p)))))
        (if (blocked candidate)
            (let ((step (v (v-x candidate) (+ (v-y candidate) 0.36) (v-z candidate))))
              (if (and (actor-ground a) (not (blocked step)))
                  (setf p step)
                  (if (eq axis 'x) (setf (v-x velocity) 0) (setf (v-z velocity) 0))))
            (setf p candidate))))
    (let* ((next-y (+ (v-y p) (* dt (v-y velocity))))

01 / NOTES

Links for lists, indexes for vectors

A list is a chain of cons cells. first and rest access its head and tail; push adds to the head and pop removes it. push changes the list held in its place. Items and short-lived effects are frequently added and removed, so this game stores them in lists. cons pairs two values: (cons ix iz) creates a dotted pair with a numeric tail, not an ordinary two-element list.

A vector is a one-dimensional array accessed by index, as in (aref ammo 2). #(180 24 16 16) is a vector literal; create mutable instance data with (vector 180 24 16 16). Destructively changing a constant literal can cause undefined behavior involving compilation or shared objects. Ammo order must match weapon indexes.

COMMON LISP / WORKBENCH
(let ((items nil))
  (push :health items)
  (push :rail items)
  (pop items)) ; => :RAIL
 
(let ((ammo (vector 180 24 16 16)))
  (decf (aref ammo 2))
  (aref ammo 2)) ; => 15
02 / NOTES

Express an operation on a collection

mapcar applies a function to each element and creates a new list; reduce combines a collection into one value. Sum bot kills with (reduce #'+ actors :key #'actor-kills). remove-if returns a list without matching elements. delete-if is permitted to modify its input destructively, so use it carefully when a list may be shared.

sort and nreverse are also permitted to modify their inputs. ranked sorts (copy-list *actors*) so presentation order does not reorder the game’s actor list. Always retain the returned value of a destructive operation: the head of the result may be a different cell.

COMMON LISP / WORKBENCH
(mapcar (lambda (x) (* x 2)) '(1 2 3))

(remove-if #'minusp '(-1 0 3 -2))

Give the map an address system

build-nav uses a hash table from coordinates (ix . iz) to node indexes. Node index 0 is valid. In Common Lisp, 0 is true, so when other does not exclude it. If NIL can itself be a stored value, use the second value from gethash to test presence. Choose an array, list, or hash table according to whether you need indexing, sequence traversal, or key lookup, rather than ranking them by a vague idea of speed.

A structure creates a vocabulary

02 / NOTES

Length, direction, and displacement

v+ adds corresponding components and v* scales them. dot3(a,b) is ax×bx + ay×by + az×bz. The square root of a vector’s dot product with itself gives its length. unit divides by that length to create a unit direction. Normalizing diagonal input (1,0,1) gives approximately (0.707,0,0.707), avoiding a diagonal-speed advantage.

Dividing by zero is an error. unit returns a zero vector when length is below 0.00001, which handles input with no keys held. flat sets y to 0 so horizontal speed can be considered separately. The HUD and speed cap use flat to avoid counting jump velocity as horizontal movement.

COMMON LISP / WORKBENCH
(defun dot3 (a b)
  (+ (* (v-x a) (v-x b))
     (* (v-y a) (v-y b))
     (* (v-z a) (v-z b))))
(defun len (a) (sqrt (dot3 a a)))
(defun unit (a)
  (let ((n (len a)))
    (if (< n 0.00001) (v 0 0 0) (v* a (/ n)))))

03 / NOTES

Share a reference or create a new value

(let ((b a)) …) does not copy the structure referenced by a. Setting v-x through b changes the same object visible through a. In contrast, the game’s v+, v-, and v* return fresh v structures. Returning a new value for a calculation helps avoid intermediate results accidentally overwriting the old position.

Creating many fresh objects costs allocation and garbage collection. Start with clear, correct calculations, measure, then reuse vectors only where frequent updates justify it. Making everything destructive too early can lose the old position that collision detection needs—a larger problem than the allocation you tried to save.

Give the world a consistent second

What you will learn

  1. Understand position, velocity, acceleration, and their units
  2. Implement a fixed step and an accumulator
  3. Separate input, simulation, and rendering
01 / NOTES

A frame is not a unit of time

Adding 0.1 to position per rendered frame moves 3 units per second at 30 FPS and 14.4 at 144 FPS. Use velocity multiplied by seconds. Gravity changes velocity per second: first vy -= gravity×dt, then y += vy×dt. This is semi-implicit Euler integration. It is not identical to the analytic solution, but a fixed step makes runs comparable.

The game’s +tick+ is 1/120 second. Rendering rate may vary, but simulation uses that same interval. Read input once per rendered frame and pass it to the required updates. A Space press is briefly stored in jump-buffer so it is not lost between a rendered frame and a physics step.

COMMON LISP / WORKBENCH
(let ((position 0.0) (velocity 12.0) (dt (/ 1.0 120)))
  (dotimes (i 120)
    (incf position (* velocity dt)))
  position) ; approximately 12.0
Laboratory / TIMESTEP
02 / NOTES

Keep the remaining fraction of time

Add each rendered frame’s dt to an accumulator. While it holds at least 1/120 second, call tick-game and subtract one step. A 1/60-second frame needs two updates; at 1/144 second, some frames need none and some need one. Carry the remainder forward rather than rounding it away.

Updating thousands of times after a long stall can create a spiral of trying to catch up and stalling again. main caps frame dt at 0.1 second and resets the accumulator while paused. This does not reproduce every second of a stall; it prioritizes returning to interactive play. Online games require a separate synchronization design.

COMMON LISP / WORKBENCH
(incf accumulator dt)
(loop while (>= accumulator +tick+) do
  (tick-game +tick+ wish fire jump-held)
  (decf accumulator +tick+))

Function order becomes game order

tick-game updates timers, respawns dead actors or moves living ones, advances rockets and pickups, then checks match completion. render-frame draws that resulting state. If damage were applied during drawing, a headless test would not produce combat. A 120-second bot simulation works without a screen because updating is independent of rendering.

A fixed step alone does not make a game fully deterministic. Random seed, actor order, floating-point behavior, and the input sequence also matter. The reproducible test fixes randomness using seed-random-state. The lab illustrates time stepping; it is not a replay of the complete game.

What a box needs

The solid structure stores center, size, color, and accent color. It is not named block because that conflicts with Common Lisp’s BLOCK. :conc-name block- still produces accessors such as block-pos. A box centered at (0,0.6,0) with size (7,1.2,7) has its top at y=1.2 and bottom at y=0.

02 / NOTES

The ground is more than y = 0

floor-at examines tops of boxes covering x,z and returns the highest surface no higher than below. That bound prevents teleporting onto overhead platforms. Spawn placement queries the highest surface; movement queries up to current height plus a small step allowance. The same query handles ground, terraces, and stairs.

Stairs are a sequence of thin boxes with increasing heights. The 0.3125 step height is below the 0.36 automatic step allowance. Those numbers work together. Changing only one can create stairs that look usable but cannot be climbed. Map changes need collision and bot climb limits checked as well.

player-input turns WASD into a unit wish direction. accelerate projects current horizontal velocity onto wish with a dot product, then adds only what is missing toward a target speed of 12. Collision approves or rejects a proposal

move-body proposes x and z motion separately. If blocked, it rejects that axis and zeroes its velocity. The other axis can still move, producing wall sliding. body-overlaps approximates a player with radius 0.42 and height 1.8 by overlap against box bounds.

This is not an exact capsule test; horizontally it resembles expanded box bounds. The 120 Hz step and speed cap keep per-step movement small, but they do not guarantee continuous collision with every thin obstacle. A much faster dash may need smaller movement substeps or swept collision.

Three kinds of vertical behavior

When a grounded actor meets a small step, movement tries the candidate 0.36 units higher. If descending motion would cross a floor, set position to the floor, vy to 0, and ground to T. A normal jump sets vy to 10.2 and ground to NIL. With gravity 28, the analytic rise is 10.2²/(2×28) ≈ 1.86; semi-implicit integration gives a slightly different result. A jump-strength change also affects reachable platforms, bot climb limits, and the distinction from a wall kick.

01 / NOTES

When a ray meets a box

A ray is origin + direction×t. With a unit direction, t represents distance. Each box axis has low and high bounds. When d is nonzero, compute t1 = (low−origin)/d and t2 = (high−origin)/d. A hit exists if the intervals for all axes overlap. near is the largest entry and far the smallest exit; near > far means no overlap.

Do not divide on an axis whose d is nearly 0. If origin lies outside that slab, there is no hit; if inside, continue with the other axes. A ray starting inside a box can return near = 0. NIL means no hit and is different from distance 0. min and max handle reversed entry/exit values for negative directions.

         (cost (make-array n :initial-element most-positive-single-float))

                               (if (< (+ (aref cost a) (distance3 (aref *nav* a) (aref *nav* end)))

Use macros to shape the notation

01 / NOTES

Compute values or construct expressions

A function normally receives evaluated arguments. A macro receives unevaluated forms and returns code to evaluate in their place. native generates both an FFI declaration and a wrapper converting arguments to single precision. A single declaration pattern reduces mismatched types across dozens of bindings.

Macros are not a runtime speed trick. Use a function for ordinary calculations. A macro is useful when wrapping unevaluated bodies, operating on a caller’s place, or generating related definitions. The important criterion is whether its expansion remains understandable.

02 / NOTES

Three marks for constructing code

Backquote constructs a list template. Comma inserts an expression’s value, and ,@ inserts each element of a list at that position. native uses ,@ to insert a sequence of argument declarations rather than one nested list. Unlike quote, backquote lets selected parts of the template be computed.

Inspect one expansion level with macroexpand-1. If the same argument form appears twice in expanded code, its effects may happen twice. gensym creates an uninterned temporary symbol to avoid capturing a variable with the same name in the caller.

Stop at a readable boundary

(defmacro native (name result &rest args)
  (let ((raw (intern (concatenate 'string "%" (symbol-name name))))
        (types '((float . sb-alien:single-float) (int . sb-alien:int)
                 (uint . sb-alien:unsigned-int) (string . sb-alien:c-string)

       (sb-alien:define-alien-routine
           (,(substitute #\_ #\- (string-downcase (symbol-name name))) ,raw)
           ,(cdr (assoc result types))
         ,@(mapcar (lambda (a) `(,(car a) ,(cdr (assoc (cadr a) types)))) args))

         (sb-int:with-float-traps-masked (:divide-by-zero :invalid :overflow)
         (,raw ,@(mapcar (lambda (a)

                            (float `(float ,(car a) 1.0f0))
                            (int `(round ,(car a)))
                            (t (car a)))) args)))))))

(defun route (from to)
  (let* ((start (nearest-node from)) (end (nearest-node to)) (n (length *nav*))
         (cost (make-array n :initial-element most-positive-single-float))
         (parent (make-array n :initial-element -1)) (closed (make-array n :initial-element nil))
         (open (list start)))
    (setf (aref cost start) 0.0f0)
    (loop while open do
      (let ((current (reduce (lambda (a b)
                               (if (< (+ (aref cost a) (distance3 (aref *nav* a) (aref *nav* end)))
                                      (+ (aref cost b) (distance3 (aref *nav* b) (aref *nav* end)))) a b)) open)))
        (setf open (delete current open))
        (when (= current end)
          (return-from route (loop for i = end then (aref parent i) until (= i start) collect (aref *nav* i) into path finally (return (nreverse path)))))

        (dolist (next (aref *nav-links* current))
          (unless (aref closed next)
            (let ((new (+ (aref cost current) (distance3 (aref *nav* current) (aref *nav* next)))))
              (when (< new (aref cost next))

Glossary

S-expression ↗

The representation used for Lisp data and code, including symbols and lists.

REPL ↗

An interactive loop that reads, evaluates, and prints expressions.

Common Lisp ↗

The language used here, rather than a particular runtime.

SBCL ↗

The compiler and runtime used here, also providing FFI and image saving.

Form ↗

An expression to evaluate; not necessarily a function call.

Symbol ↗

An object representing a name, usable for variables or functions.

Keyword ↗

A self-evaluating symbol such as :health.

NIL ↗

False and the empty list; 0 is not NIL.

Quote ↗

Returns a form as data without evaluating it.

Lexical scope ↗

Local binding whose visibility follows the source’s lexical structure.

Special variable ↗

A dynamically scoped variable declared with forms such as defvar.

Place ↗

A location writable by setf, such as a variable, slot, or array element.

Lambda ↗

A function created without a global name.

Multiple values ↗

Several results returned by values; not the same as a list.

Cons ↗

A two-field cell used for lists and dotted pairs.

Vector ↗

In Lisp, a one-dimensional array; the game’s v structure represents a mathematical 3D vector.

Hash table ↗

A key-to-value data structure whose comparison test matters.

Structure ↗

A data type with named slots, defined with defstruct.

Dot product ↗

The sum of corresponding component products; used for projection and length.

Normalization ↗

Scaling a nonzero vector to length 1.

Delta time ↗

Elapsed time since the previous step, measured here in seconds.

Accumulator ↗

A value retaining time not yet consumed by simulation steps.

FFI ↗

An interface for calling functions implemented in another language.

ABI ↗

Machine-level conventions for arguments, results, and layout.

AABB ↗

An axis-aligned box, whose collision can be expressed through intervals.

Normal ↗

A direction perpendicular to a surface, used for wall-kick push.

Cooldown ↗

Remaining time until an action can trigger again.

Hitscan ↗

A shot resolved by ray intersections at firing time rather than a moving projectile.

Slab test ↗

A box-ray test using the overlap of axis intersection intervals.

Impulse ↗

An immediate velocity change, separate from damage.

Occlusion ↗

Blocking sight or splash by intervening geometry.

A* ↗

A path search using known cost g and estimated cost h.

Heuristic ↗

An estimate guiding search; here, distance to the destination.

Macro ↗

A construct receiving unevaluated forms and returning an expansion.

Gensym ↗

An uninterned symbol used to avoid temporary-binding name collisions.

Condition ↗

Lisp’s mechanism for signaling situations such as errors.

Backtrace ↗

The sequence of function calls leading to a failure.

FASL ↗

A compiled file produced by compile-file and loaded with load.

GC ↗

Garbage collection reclaiming memory no longer in use.

Regression ↗

A previously working behavior broken by a later change.
